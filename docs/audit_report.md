# Аудит исходного файла

**Исходник:** `анализ_сеть_последняя_с_группами.txt`  
**Объём:** ~1809 строк, Python 3  
**Кодировка на диске:** Windows-1251 (cp1251)  
**Назначение:** модуль сетевого анализа инвентаризаций v3.0

## 1. Краткий вердикт

Рабочий монолитный скрипт с зрелой бизнес-логикой анализа излишков/недостач/пересорта и богатым Excel-экспортом. Готов к рефакторингу в модульный репозиторий без изменения правил расчёта. Главные риски для production: абсолютный путь `DEFAULT_DIR`, CLI на tkinter, отсутствие автотестов и смешение UI/парсинга/экспорта в одном файле.

## 2. Определение

| Вопрос | Ответ |
|--------|--------|
| Язык | Python 3 (`from __future__ import annotations`) |
| Назначение | Анализ нескольких магазинов за N дней: излишки, недостачи, пересорт, мероприятия |
| Сценарий | Выбрать xlsx → распарсить TDSheet → обогатить → посчитать overlaps/метрики → Excel-отчёт |
| Зависимости | `pandas`, `numpy`, `openpyxl`; опционально `tkinter` для диалога выбора файла |
| Структура | Конфиг → стили → нормализация → парсер → overlap → сценарии → метрики → Excel → CLI |

## 3. Что оставить

- Алгоритм `find_peresor` / однородность категорий
- Правила сценариев СЦ-1…СЦ-7
- Метрики магазинов/документов/SKU и «чистые недостачи»

## 5. Что переименовать (смыслово)

- `DEFAULT_DIR` → `INVENTORY_DATA_DIR` (env, опционально)
- Монолитный `main()` → CLI (`main.py`) + UI (`app.py`)
- `build_report` остаётся фасадом пайплайна

## 6. Что убрать в конфиг

- `PERIOD_DAYS`, `MIN_OVERLAP_SCORE`
- Пороги сценариев 50 000 / 10 000 / 1 000
- Guardrail объёма пар (`2_500_000`, `head(1200)`)
- `ENABLE_CROSS_STORE`
- Имена non-retail магазинов и exclude-keywords (уже константы настроек)

## 7. Критично для production-ready

1. **Убрать обязательный абсолютный путь** — сделано через env / upload.
2. **Не полагаться на tkinter в облаке** — Streamlit file_uploader.
3. **Зафиксировать зависимости** — `requirements.txt`.
4. **Smoke-тесты** — `tests/test_smoke.py`.
5. **Документация деплоя** — `docs/deployment.md`.
6. **Кодировка исходника cp1251** — проектные файлы в UTF-8.
7. **Квадратичность matching** — guardrail сохранён; на больших файлах возможен timeout на Cloud.

## 8. Риски исходника (сохранены как известные ограничения)

- Эвристическая классификация категорий → возможны `fallback` группы
- Cross-store overlap — аналитика, не операционный пересорт
- `calc_document_metrics` повторно вызывает `find_peresor` (дороже, но логика не менялась)
- Нет явной лицензии / секретов (секретов в коде не было)

## 9. Неоднозначности и выбранное решение

| Неоднозначность | Решение |
|-----------------|---------|
| Целевая папка уже заполнена Excel-выгрузками | Создан подкаталог `network_inventory_analyzer/` |
| Нужен ли cross-store по умолчанию | Как в оригинале: `False` / `ENABLE_CROSS_STORE=0` |
| Сохранять ли tkinter в CLI | Да, с fallback на консольный выбор |
